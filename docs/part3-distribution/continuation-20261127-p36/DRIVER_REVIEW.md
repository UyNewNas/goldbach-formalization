**Effective dependency search path.** Original driver lines 52–58 hash each path in the original accepted warm object tree. The recorded LEAN_PATH begins with the new overlay's `objects` directory, followed by package directories. The original warm object root does not appear in this path. Checking the original path alone cannot detect a stale or misdirected overlay entry. Check the overlay entry for every one of the 286 project dependencies against the same accepted digest, and verify that the first LEAN_PATH directory is the checked overlay and the remaining entries agree with the accepted paths. Do this both before and after replay. This is a path-binding check with reusable cache data.

**Checker identity and reporting.** Original driver lines 78–81 and 124–125 check that the checker stayed unchanged during the run. The accepted toolchain checker digest is recorded in `accepted-warm-common/RECEIPT.json` at line 30 as `ed46f21c763051c26f89481096cbaaf5db9665d674d602e3daf3391613ba0e6a`. Compare the observed digest with this value. On a reused acceptance directory the original driver writes its RUNNING state only after the first subprocess returns. A failure while opening startup files, or interruption of the first check, can leave an earlier success on disk. A fresh per-attempt directory or an early RUNNING record plus matching current successful terminal receipt resolves this ambiguity. A failed subprocess has nonzero driver status even in the original implementation.
