# Residual-payment verification driver review

The compile overlay uses 315 previously accepted project modules. It begins with the previous frontier job's 288 warm entries, then adds its 27 defining owners. Each new source pin must match the independently copied local expected hash. The previous audit identifies all 27 source/object pairs and the previous owners' objects must be regular compiled outputs. Before the first compile and after every attempt, the driver compares the original and live objects, every corresponding source, and the original prior report bytes. A provisional seven-owner run is a diagnostic for the submitted source version. The final eight-owner scope includes the signed rounded density owner.

| Component | Binding |
|---|---|
| `prepare_acceptance.py` | For every requested defining module, match the successful strict record to the exact attempt, module name, source and non-symlink object. Verify the generated original-renderer audit digest. |
| `verify_owned.py` | Recheck the 315 previous source and object entries against their original and live paths, every owned source/object and the previous completed report. Run one exact Lean kernel replay per new owner and the original renderer/validator's full type and transitive-axiom inventory. Correlate replay stdout with its sole defining module. |
| `export_owned.py` | Check the audit driver digest, owner pins, stage logs and zero exits. Include the strict compile snapshots and logs, complete typed declarations, prior source expectations and pinned helper bytes. Export one manifest-checked xz payload with the audit verification ID. |
| `verify_export_locally.py` | Require original success and nontruncated stdout, the full ordered eight compile records, the identical original audit and export, and an exact byte-for-byte local reconstruction of each owner and helper. Recheck every source locally, every exported defining object, each replay and its command, the audit renderer and its inventory. Reconstruct the 315 input entries from the independently retrieved previous group's successful terminal, stdout, local receipt and archived report/pins. The previous report digest must agree with the new warm manifest and current audit. |

A rejection check passed using the previously recorded single-owner strict compile event as the input to the new preparation helper with an intentionally changed local source in a temporary directory. The helper rejected the changed bytes before writing owned pins. A prior compile-only terminal and an unrelated successful original job also both failed the inherited local acceptance contract before a success receipt could be issued. These checks test the rejection paths. They contribute no kernel credit.

A complete success receipt can only be generated once all eight defining owner records, all original archives and both successful job identities are available. The receipt distinguishes two existing compatibility suppliers from six new proof owners.
