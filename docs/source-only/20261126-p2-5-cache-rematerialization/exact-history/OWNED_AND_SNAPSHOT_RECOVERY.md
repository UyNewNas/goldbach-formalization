# Exact recovery of owned JSON; unresolved historical snapshot envelopes

Four original owned JSON files were reconstructed from already retained accepted owner data and audit log markers using the original runner serialization. Every file matches its original byte count and SHA256. The four payload files total 26,036 bytes. `OWNED_JSON_RECONSTRUCTION.json` records the source receipts, audit logs, method, and expected identities; `OWNED_PAYLOAD_MANIFEST.json` supplies four file entries in the existing recovery resolver format. These entries may be merged with the current external payload sidecar without changing the frozen recovery runner or selection.

The five missing `COMPLETE_EXTERNAL_BEFORE.json` files were not reconstructed. `EXTERNAL_SNAPSHOT_BLOCKERS.json` records the bounded inspection and precise blocker: the original snapshot-specific `started_utc` and `finished_utc` values are absent from the inspected full receipts, original capsules, task logs, and summaries. The old runners call the clock separately for these fields and only save their values inside the missing snapshots. Overall run or stage times are different calls and do not determine these values.

All five runners construct the same envelope, and every external object/companion hash in all five frozen receipt dictionaries matches the preserved upstream arithmetic snapshot: 5,312 modules and 10,624 companions. Copying those deterministic fields with two 32-character diagnostic masks gives the expected 4,302,154-byte length. No masked envelope was written or advertised as a payload. A match after removing timestamp fields would not establish the required historical byte identity.

Consequently the four owned metadata objects are recoverable now; these five snapshot envelopes require another original byte copy or the two exact historical timestamp values per file. This audit did not scan remote storage, run Lean, recreate failed runs, grant formal credit, or change the frozen recovery runner/selection.
