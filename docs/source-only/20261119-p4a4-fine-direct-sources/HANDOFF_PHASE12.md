## Numerical test and its exact limit

`guillotine_check.cpp` implements the same finite ordered-axis, midpoint and fuel decisions with little-endian 17-byte records. The only representation difference is that C++ partitions each array range in place, whereas Lean's `List.filter` retains ordering; axis eligibility depends only on membership, so permutation leaves the finite decision unchanged. `verify_guillotine.py` independently implements the Lean decision in Python and compares it with the C++ program on 325 deterministic small cases, including empty/singleton, dyadic touching, overlap, duplicates, and a nondyadic touching example. The two implementations agreed on all cases (202 accepted and 123 rejected). These tests are evidence about the translation; they are not a formal proof of equivalence.

This tree starts from the global 16-bit cube and follows the Lean first-axis rule, so its node count is not to be confused with the older research producer's separate per-root guillotine count.

The original authoring self-test initially expected arbitrary half-open touching boxes `[100,200)` and `[200,300)` to pass; it returned exit 3. Diagnosis showed the fixed dyadic midpoint procedure cannot necessarily separate arbitrary disjoint boxes, so that self-test expectation—not the original dataset—was wrong. This is not a claim that the sufficient midpoint procedure decides all disjoint box families.
