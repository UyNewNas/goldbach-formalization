## Calling the published updater

The parent execution wrapper must obtain this exact script from I and pass I's actual full commit. For example, with `cutoff_repair_entrypoint` pointing to those retained published bytes and `cutoff_repair_commit` set to I:

```bash
python3 -B "$cutoff_repair_entrypoint" --source-commit "$cutoff_repair_commit" --apply
```

The outer invocation uses the existing serialized lane 0 and verifies the unchanged dirty Git state. `--inside-lane` is internal. An optional `--check` performs the same read-only binding work without installing sources or removing the setup; it is not required as a separate cloud job before `--apply`.

A successful source-only application records `SOURCE_REPAIR_RESULT.json` with status `EXACT_CUTOFF_EXPRESSION_SOURCE_REPAIR_VERIFIED_NOT_COMPILED`. The separately authorized I driver may then compile only Cutoff. This updater never invokes that driver and never recompiles HB or Support.

An unknown source, artifact, missing receipt, changed context or unexpected extra graph change causes HOLD. If a prior attempt archived the exact setup but failed before installation, its durable archive receipt is required before continuing. A source already changed to the postimage does not qualify for another mutation; inspect the retained successful result instead. Existing failure evidence and backups are retained.
