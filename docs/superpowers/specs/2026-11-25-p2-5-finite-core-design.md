# P2.5 finite occurrence core

## Intent and constraints

The November 6 manuscript requires one exact partition of the original
negative-inner sum into its fourteen selected source families and one
unchanged complement. The new finite partition already has a source
implementation. Its initial import inherited 1688 project modules because
finite definitions and scheduled R17 consumers share owners.

This is a source-organization decision within the authorized P2.5 work.
The mathematical object, public theorem names, assumptions, signs,
weights, full `(s,d)` occurrences and complement must remain unchanged.
No quantitative PP input or scheduled endpoint is supplied by this move.

## Approaches considered

1. Install and compile the original 1688-module closure. This preserves
   source packaging, but loads unrelated scheduled and numerical consumers
   before an elementary finite identity can be checked.
2. Move the minimum 22 existing declarations. The graph becomes 362
   modules, but part of the original finite API remains coupled to the
   scheduled owner.
3. Move all 31 relevant existing declarations, including the original
   thirteen-declaration finite fibre API. The graph is also 362 modules,
   and the finite API has one complete owner.

The implementation uses option 3. This choice reuses the original proof
bodies and leaves the scheduled R17 consumers in their original owners.
It does not replace those consumers with stronger assumptions.

## Source layout

`P2Saving16NegativeFiniteCore` imports the existing tagged beta attachment,
full87 history core, full87 ownership and saving16 source binding. Public
names remain in their original namespaces. The 31 declarations come from
seven existing source owners. Five missing support modules are restored
from exact existing sources; the original 355-module identity source
graph is not modified by this extraction.

`P2Saving16FourteenNegativeFibrePartition` changes only its import to the
new finite core. Its two definitions and fourteen theorem bodies retain
their original source text.

The seven heavy owners are not installed in production. Complete
post-extraction copies and a declaration movement manifest are retained
in the source-only package. Any later installation must use those
postimages, preventing duplicate declarations with the finite core.

## Explicit exceptions and verification

The private helper `attach_indicator` keeps its source declaration and
body, but Lean's generated private kernel name necessarily changes with
its module. The manifest must distinguish that from public-name identity.
The deprecated Set member theorem in `mem_trim` is replaced by its exact
alias `mem_ofPred_eq`; the same change is needed in the reused history
core's `mem_core`. These two locations are recorded separately. Fourteen
term occurrences of the existing `universe` identifier are quoted as
`«universe»`, preserving its name while accepting current Lean syntax.
These compatibility changes are distinguished from byte-identical body
movement.

Independent review checks source provenance, every moved declaration,
namespaces and context, the remaining owners, absence of duplicate
production declarations, and the actual import closure. Strict Lean
compilation, stock independent replay and complete owned-declaration
audits remain mandatory before acceptance. Until then every new source
is a compilation candidate, and P2.5 remains open.
